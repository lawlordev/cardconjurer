# Set Conjurer v0.1.0-beta.5

Set Conjurer beta.5 expands card-authoring workflows, improves desktop polish, and makes the Windows release trustworthy with required Azure Artifact Signing.

## Highlights

- Create and print double-sided cards as one logical card while editing each face independently.
- Recognize the complete reviewed Magic Set Editor keyword catalog, add reminders on demand, and install keyword definitions as an independently updatable required content pack.
- Fit rules text around holo stamps, power/toughness boxes, loyalty areas, and Battle defense areas without over-shrinking safe lines.
- Prevent Miracle and legendary-crown title treatments from colliding, and restore the Dark P/T component toggle.
- Adjust layout values with accessible live minus/plus controls across text, frames, set symbols, and serialized card fields.
- Open Settings immediately, show consistent progress while Settings or print pages load, and retain responsive drawer behavior.
- Integrate macOS window controls into the compact app header and provide a branded drag-to-Applications installer.
- Distinguish Dev, Beta, and Stable builds with matching in-app indicators and transparent, platform-normalized icon footprints—including the grayscale Beta Dock icon.
- Ship the Windows x64 installer through the fail-closed Azure Artifact Signing lane.

## Upgrade and compatibility notes

- This is a prerelease. Back up important work before installing any beta build.
- Existing beta.4 workspaces and installed content-pack generations remain in place; this release adds no database migration, service deployment, or destructive data operation.
- Existing single-faced cards remain compatible. A second face is created only when a paired directional frame is selected.
- Set Symbols, Keywords, and Standard remain required content packs. The application continues to accept the existing compatible pack catalog; no content-pack release is required for beta.5.
- Windows publishing is allowed only when Azure Artifact Signing succeeds for the packaged app, Squirrel updater, and final Setup executable. The workflow verifies each critical Authenticode signature before publication.
- macOS arm64 and Intel application bundles and DMGs must pass Developer ID signing, notarization, stapling, and Gatekeeper assessment before publication.

## Release gates and tester steps

1. Run `npm ci`, `npm run packs:compile`, `npm run keywords:check`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:keywords`, and `npm run test:electron` with Node 24.
2. Require the pull-request Desktop CI aggregate, macOS arm64 package, macOS Intel package, Windows package/install smoke, and verification jobs to pass at the release-candidate SHA.
3. Merge with a merge commit, then require the `master` Desktop CI run for the merge SHA to pass before tagging.
4. Create immutable tag `v0.1.0-beta.5` at the verified merge commit and dispatch **Release Set Conjurer** from `master` with `channel=beta`, `publish=true`, and `windows_signing=required`.
5. Require macOS signing/notarization/stapling checks and Azure Authenticode checks to pass before the publish job creates the prerelease.
6. Verify the public prerelease is tied to the immutable tag and exposes `Set-Conjurer-arm64.dmg`, `Set-Conjurer-x64.dmg`, `Set-Conjurer-Windows-x64-Setup.exe`, Squirrel metadata/package assets, `WINDOWS-SIGNING.txt`, and `SHA256SUMS`.
7. Verify every published digest against `SHA256SUMS`, confirm `WINDOWS-SIGNING.txt` reports signed Azure verification, and confirm immutable download URLs return successfully.
8. On a disposable profile, upgrade beta.4 to beta.5 and confirm workspace data, active packs, shortcuts, Installed Apps registration, and the running version survive.
9. Exercise the launch, editing, keyword, Settings, print/export, and packaging journeys in the matrix above. Record human acceptance separately; automated checks do not mark it complete.

## Rollout, stop conditions, and recovery

- **Owner:** repository maintainer or authorized release operator.
- **Production mutation:** the new immutable Git tag and GitHub prerelease only. No website, database, service, migration, content-pack release, or external data store is changed.
- **Stop before publication:** any PR/master CI failure, tag/package version mismatch, missing Azure configuration, invalid Windows signature, macOS signing/notarization failure, missing installer, checksum mismatch, or package smoke failure.
- **Stop after publication:** missing/corrupt asset, wrong tag or version, failed immutable download, invalid signature, or a confirmed workspace/upgrade regression.
- **Recovery:** do not replace assets under `v0.1.0-beta.5`. Mark a bad prerelease clearly, retain beta.4 immutable installers, fix forward on `master`, and publish a higher immutable beta tag. User workspaces and pack generations are not modified by release publication itself.
